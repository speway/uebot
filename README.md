# Уебот · Расписание П2‑23

Telegram: @msutf_p223_schedule_bot. Python 3.11+ на Linux, без сторонних Python-библиотек.

## Что уже сделано

- Бот зарегистрирован через аккаунт владельца, настроены описание и команды.
- Получение текущей и следующей недель EduPage проверено 11 сентября 2026 года; недельная маска применяется к выбранной дате, поэтому пустая будущая неделя не копирует текущую.
- Фильтр только по точному коду П2-23; общие занятия с другими группами включаются.
- Уведомления при новой неделе и при подтверждённом изменении будущих занятий.
- Команды /today, /tomorrow, /next, /when, /free, /rooms, /week, /nextweek, /roast, /status, /help.
- /next показывает текущую или ближайшую пару и живой обратный отсчёт до неё.
- /when показывает время до начала или конца пары, /free ищет ближайший подтверждённый свободный учебный день, /rooms собирает аудитории на сегодня, /roast выдаёт фактический диагноз нагрузке.
- AI отвечает через /ask, прямое @упоминание или reply на сообщение бота; обычный групповой трёп не перехватывается.
- В AI передаётся только вопрос, короткий текст ответа, на который пользователь сделал reply, и публичное расписание текущей/следующей недели. Скрытая долгая история не ведётся, запросы отправляются с `store: false`.
- Читаемые текстовые сообщения с итогом дня, количеством пар, временем, преподавателем и аудиторией; одинаковые соседние пары объединяются без потери данных.
- Фактическая часть расписания остаётся буквальной и проверяемой; подписи и ответы выдержаны в намеренно матерном, насмешливом тоне группы.
- Постоянная база SQLite, защита от повторов после перезапуска, блокировка второго экземпляра.

## Статус запуска

Production запущен 10 сентября 2026 года; расширенный функционал и AI-режим подготовлены 12 сентября:

- webhook отвечает на `https://uebot.vercel.app/api/telegram` и принимает только запросы Telegram с правильным секретом;
- бот подключён к целевой группе; опубликованная текущая неделя содержит 12 занятий, а ещё не заполненная следующая показывается отдельной честной заглушкой;
- защищённый Vercel relay читает EduPage, если сеть GitHub runner не может установить прямое соединение;
- состояние публикаций хранится с ID сообщений Telegram; при таймауте источника workflow падает явно и не затирает подтверждённые данные;
- регрессионные тесты проверяют расписание, публикации, webhook, карточки и ограниченный AI-контур на Python 3.13.

Токен в репозиторий и Vercel не загружен: он хранится только в GitHub Actions Secrets. В публичной ветке `state` находятся только расписание и служебные ID сообщений.

## Запуск через GitHub + Vercel (без VPS)

1. Создать отдельный публичный репозиторий с содержимым этого каталога. Токен и `.env` не загружать.
2. Добавить бота в целевую Telegram-группу и подтвердить её ID по входящему событию. Ссылка-приглашение сама по себе не позволяет боту вступить в группу.
3. В GitHub Actions Secrets задать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `WEBHOOK_SECRET`. Workflow получает только право записи contents и запрашивает проверку раз в пять минут по расписанию GitHub.
4. Вручную запустить workflow `Check P2-23 timetable`. Первый запуск создаст ветку `state`: в ней хранятся снимок расписания и журнал отправок без токена. Новый запуск читает это состояние, поэтому не начинает рассылку заново. Файл `schedule.json` содержит только публичное расписание и статус; `state.json` дополнительно содержит служебные ID сообщений бота.
5. Импортировать репозиторий в Vercel как проект без фреймворка. Указать три переменные: `TELEGRAM_CHAT_ID`, `WEBHOOK_SECRET` (случайная строка) и `STATE_URL` (адрес файла `schedule.json` из ветки `state` на raw.githubusercontent.com). Секрет бота Vercel не нужен: Telegram выполняет метод из ответа webhook. Тот же `WEBHOOK_SECRET` защищает `/api/source`, через который workflow получает расписание при недоступности прямого маршрута к EduPage.
6. Включить для проекта Vercel AI Gateway и настроить бюджет. На Vercel приложение автоматически использует `VERCEL_OIDC_TOKEN`, поэтому отдельный AI-ключ в коде или переменных не нужен. Модель по умолчанию — `openai/gpt-5.4-mini`; её можно заменить через `AI_MODEL`, а веб-поиск отключить через `AI_WEB_SEARCH=0`.
7. После успешного развёртывания зарегистрировать через Telegram Bot API webhook: URL `/api/telegram` опубликованного проекта, `secret_token` равен `WEBHOOK_SECRET`, `allowed_updates` содержит `message`. Перед этим проверить ответ GET этого endpoint: поле `ai` должно быть `ready`. Не запускать одновременно polling-режим Docker.
8. Проверить реальные /today и `/ask что у нас завтра?` в группе, затем два последовательных запуска workflow с тестовой сменой аудитории в изолированном тестовом окружении. В рабочие данные EduPage ничего не менять.

Vercel Hobby используется для быстрых ответов на команды и защищённого чтения EduPage. Его ежедневный cron не используется для частой проверки. GitHub Actions запускает отдельные короткие задания: постоянный процесс не нужен. Планировщик GitHub может задерживать или пропускать запуски; `cron` задаёт желаемую частоту, а не гарантию запуска ровно каждые пять минут. Плановые запуски, оказавшиеся ближе четырёх минут к последней успешной проверке, завершаются без повторного обращения к EduPage — это защищает источник от очереди задержанных заданий. Запуск после обновления кода и ручной запуск проверку не пропускают. Приватные репозитории имеют лимиты минут; текущая конфигурация чтения снимка рассчитана на публичный репозиторий. После 30 минут без успешной проверки ответы бота показывают предупреждение об устаревании. Автодеплои служебной ветки `state` отключены, чтобы сохранение состояния не создавало лишние preview-сборки Vercel.

Если GitHub задержал плановый запуск, команды /today, /tomorrow и /next делают короткую живую проверку EduPage прямо через webhook и при сбое безопасно используют последний сохранённый снимок. Когда плановый запуск впервые замечает изменение, он повторно читает источник через 15 секунд в том же задании: уведомление больше не ждёт ещё одного потенциально задержанного cron-запуска.

AI-вопросы также получают свежую попытку чтения расписания. Если снимок или EduPage временно недоступны, общий вопрос всё равно обслуживается, но модель получает статус `unknown/stale` и обязана не выдумывать пары. В группе AI вызывается только явно. В личке доступ закрыт по умолчанию: разрешённые Telegram user ID перечисляются в `AI_PRIVATE_USER_IDS`; `AI_ALLOW_PRIVATE=1` сознательно открывает платные ответы всем.

Команды /week и /nextweek также пытаются обновить устаревшие данные вживую. Результат такой проверки не переиспользует старую картинку: если снимок изменился, бот отвечает свежим текстом до следующей подтверждённой публикации PNG.

При сбое сохранения в GitHub сообщение не отправляется. Резервирование отправки сохраняется до запроса Telegram; неподтверждённая отправка требует проверки оператором и не дублируется автоматически. Если одновременно недоступны relay и прямой маршрут к EduPage, workflow делает один отложенный повтор в том же задании.

## Публикации и изменения

- При первом запуске — отдельный пост на каждую опубликованную неделю.
- Подтверждённое изменение обновляет исходный недельный пост и создаёт короткое уведомление: аудитория, преподаватель, предмет или время «было → стало».
- Неоднозначный перенос не угадывается: показываются убранное и добавленное занятия.
- Повтор той же ситуации после обратного изменения тоже уведомляется — это новое событие.
- Два последовательных успешных наблюдения подтверждают изменение. Сбой между наблюдениями сбрасывает подтверждение.
- После 19:00 по Ташкенту — одно сообщение с парами на завтра, если они есть. После 23:00 пропущенный вечерний дайджест не догоняется; ночные уведомления о подтверждённых изменениях приходят тихо.
- Соседние одинаковые пары объединяются визуально с пометкой о перерыве, но в сравнении остаются отдельными занятиями.
- Меню команд, описание и короткое описание Telegram синхронизируются кодом по версии конфигурации.

## Альтернативный запуск на Linux-сервере

1. Добавить @msutf_p223_schedule_bot в нужную группу. Достаточно права отправлять сообщения; доступ ко всем сообщениям и полные права администратора не нужны.
2. На постоянном Linux-сервере с Docker Compose скопировать `.env.example` в `.env`.
3. В `.env` указать токен из BotFather и подтверждённый числовой ID нужной группы. Ссылка-приглашение не заменяет ID. ID следует получить из события `my_chat_member` или команды, присланной боту из этой группы, и сверить её название. Не угадывать ID по имени группы.
4. Для AI на обычном сервере задать `OPENAI_API_KEY` только в `.env`. Если AI не нужен, оставить значение пустым: команды расписания продолжат работать.
5. Ограничить доступ к `.env`: `chmod 600 .env`.
6. Выполнить `docker compose up -d --build`.
7. Проверить `docker compose logs --tail=40`, затем `/status@msutf_p223_schedule_bot` в группе.

При первом успешном чтении бот пришлёт доступные недельные расписания. Далее проверка каждые 300 секунд. Изменение должно повториться в двух последовательных успешных проверках; обычная задержка уведомления — около 5–10 минут плюс время запросов. Расписание на ещё не опубликованную неделю не выдумывается.

Токен хранить только в `.env` или файле секрета через `TELEGRAM_TOKEN_FILE`; не включать в репозиторий, скриншоты и общедоступные архивы. База хранится в Docker volume `schedule-data`. Для переноса на другой сервер нужно перенести и эту базу, иначе первый запуск снова отправит начальное расписание.

## Проверки

`python -m unittest discover -s tests -v`

`python bot.py --preview` — чтение живого EduPage и предпросмотр сообщений, без Telegram и без токена.

`python bot.py --once` — один цикл с реальной отправкой; нужны токен, ID группы и постоянная база. Нельзя запускать одновременно с основным процессом.

Файл `tests/edupage_130.json` — минимальная выборка реального опубликованного расписания 7–12 сентября; лишние поля и идентификаторы студентов удалены.

## Надёжность и ограничения

- Сравниваются опубликованные недельные таблицы раздела «Расписание». Отдельный раздел замен EduPage не опрашивается.
- Временные ошибки не стирают последнее успешное расписание. /status показывает последнюю успешную проверку.
- Пустая неделя после заполненной принимается только после двух одинаковых успешных чтений, затем старая карточка заменяется явной пометкой «ещё не опубликовано». Пустой источник не выдаётся за официальную отмену пар.
- Одноразовая миграция исправляет уже сохранённую ложную копию недели 14–19 сентября и обновляет прежние Telegram-сообщения по их ID даже при временной недоступности EduPage.
- При неизвестном результате отправки после сетевого обрыва повтор автоматически не производится: это предотвращает дубли, но может потребовать ручной проверки доставки. В базе запись `sent:*` остаётся в состоянии `pending`; /status показывает проблему. Оператор сверяет Telegram, затем либо помечает запись `sent`, либо удаляет конкретную резервную запись для осознанного повтора. Не удалять всю базу.
- Недельные маски EduPage фильтруются по фактической выбранной неделе. Если заголовок недели, маска, структура данных или индивидуальные звонки становятся неоднозначными, бот останавливает обработку вместо копирования чужой недели.
- Защита от двух экземпляров использует Linux flock; рекомендуется поставляемый Docker-контейнер.
- Тесты проверяют критические сценарии; абсолютное отсутствие будущих багов и доступность сторонних сервисов не гарантируются.
- AI может ошибаться в общих ответах. Расписание изолировано отдельным контекстом: пустая опубликованная неделя означает «ещё не опубликовано», а не «все пары отменены». Вопрос ограничен 2000 символами, ответ — 3300 символами, между платными запросами одного пользователя действует пауза.


## Расписание картинкой

Основной репозиторий: https://github.com/speway/uebot .

Каждая неделя публикуется как вертикальная PNG-карточка шириной 1080 px: крупные дневные блоки, объединённые двойные пары, время, преподаватели, аудитории и компактные выходные без пустой сетки. Для ещё не опубликованной недели используется отдельная карточка-заглушка, которую нельзя принять за отмену занятий. После подтверждения изменения обновляется та же картинка. Через Vercel команды /week и /nextweek возвращают изображение, /today, /tomorrow и /next — текст. На Ubuntu runner нужны Pillow и DejaVu Sans. Токен хранится только в GitHub Actions Secrets.
