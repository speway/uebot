# Уебот · Расписание П2‑23

Telegram: @msutf_p223_schedule_bot. Python 3.11+ на Linux, без сторонних Python-библиотек.

## Что уже сделано

- Бот зарегистрирован через аккаунт владельца, настроены описание и команды.
- Получение двух опубликованных недель EduPage проверено 9 сентября 2026 года.
- Фильтр только по точному коду П2-23; общие занятия с другими группами включаются.
- Уведомления при новой неделе и при подтверждённом изменении будущих занятий.
- Команды /today, /tomorrow, /week, /nextweek, /status, /help.
- Читаемые текстовые сообщения с жирным временем, предметом, преподавателем и аудиторией. Без цветной сетки; Telegram сам применяет тему пользователя.
- Постоянная база SQLite, защита от повторов после перезапуска, блокировка второго экземпляра.

## Статус запуска

Production запущен 10 сентября 2026 года:

- webhook отвечает на `https://uebot.vercel.app/api/telegram` и принимает только запросы Telegram с правильным секретом;
- бот подключён к целевой группе и успешно опубликовал две недели — по 12 занятий, обе PNG-картинки и вечерний дайджест;
- защищённый Vercel relay читает EduPage, если сеть GitHub runner не может установить прямое соединение;
- последний проверенный production workflow прошёл полностью, состояние доставки подтверждено ID сообщений Telegram;
- 38 регрессионных тестов проходят на Python 3.13.

Токен в репозиторий и Vercel не загружен: он хранится только в GitHub Actions Secrets. В публичной ветке `state` находятся только расписание и служебные ID сообщений.

## Запуск через GitHub + Vercel (без VPS)

1. Создать отдельный публичный репозиторий с содержимым этого каталога. Токен и `.env` не загружать.
2. Добавить бота в целевую Telegram-группу и подтвердить её ID по входящему событию. Ссылка-приглашение сама по себе не позволяет боту вступить в группу.
3. В GitHub Actions Secrets задать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `WEBHOOK_SECRET`. Workflow получает только право записи contents и запрашивает проверку раз в пять минут по расписанию GitHub.
4. Вручную запустить workflow `Check P2-23 timetable`. Первый запуск создаст ветку `state`: в ней хранятся снимок расписания и журнал отправок без токена. Новый запуск читает это состояние, поэтому не начинает рассылку заново. Файл `schedule.json` содержит только публичное расписание и статус; `state.json` дополнительно содержит служебные ID сообщений бота.
5. Импортировать репозиторий в Vercel как проект без фреймворка. Указать три переменные: `TELEGRAM_CHAT_ID`, `WEBHOOK_SECRET` (случайная строка) и `STATE_URL` (адрес файла `schedule.json` из ветки `state` на raw.githubusercontent.com). Секрет бота Vercel не нужен: Telegram выполняет метод из ответа webhook. Тот же `WEBHOOK_SECRET` защищает `/api/source`, через который workflow получает расписание при недоступности прямого маршрута к EduPage.
6. После успешного развёртывания зарегистрировать через Telegram Bot API webhook: URL `/api/telegram` опубликованного проекта, `secret_token` равен `WEBHOOK_SECRET`, `allowed_updates` содержит `message`. Перед этим проверить ответ GET этого endpoint. Не запускать одновременно polling-режим Docker.
7. Проверить реальный /today в группе, затем два последовательных запуска workflow с тестовой сменой аудитории в изолированном тестовом окружении. В рабочие данные EduPage ничего не менять.

Vercel Hobby используется для быстрых ответов на команды и защищённого чтения EduPage. Его ежедневный cron не используется для частой проверки. GitHub Actions запускает отдельные короткие задания: постоянный процесс не нужен. Планировщик GitHub может задерживать или пропускать запуски; `cron` задаёт желаемую частоту, а не гарантию запуска ровно каждые пять минут. Запуски, оказавшиеся ближе четырёх минут к последней успешной проверке, завершаются без повторного обращения к EduPage — это защищает источник от очереди быстрых push-событий, но не уменьшает обычную частоту cron. Приватные репозитории имеют лимиты минут; текущая конфигурация чтения снимка рассчитана на публичный репозиторий. За последние 60 минут без успешной проверки ответы бота показывают предупреждение об устаревании. Автодеплои служебной ветки `state` отключены, чтобы сохранение состояния не создавало лишние preview-сборки Vercel.

При сбое сохранения в GitHub сообщение не отправляется. Резервирование отправки сохраняется до запроса Telegram; неподтверждённая отправка требует проверки оператором и не дублируется автоматически. Если одновременно недоступны relay и прямой маршрут к EduPage, workflow делает один отложенный повтор в том же задании.

## Публикации и изменения

- При первом запуске — отдельный пост на каждую опубликованную неделю.
- Подтверждённое изменение обновляет исходный недельный пост и создаёт короткое уведомление: аудитория, преподаватель, предмет или время «было → стало».
- Неоднозначный перенос не угадывается: показываются убранное и добавленное занятия.
- Повтор той же ситуации после обратного изменения тоже уведомляется — это новое событие.
- Два последовательных успешных наблюдения подтверждают изменение. Сбой между наблюдениями сбрасывает подтверждение.
- После 19:00 по Ташкенту — одно сообщение с парами на завтра, если они есть. После 23:00 пропущенный вечерний дайджест не догоняется; ночные уведомления о подтверждённых изменениях приходят тихо.
- Соседние одинаковые пары объединяются визуально с пометкой о перерыве, но в сравнении остаются отдельными занятиями.
- Описание и приветствие: «Бот чисто для своих кентиков из лучшей группы П2‑23».

## Альтернативный запуск на Linux-сервере

1. Добавить @msutf_p223_schedule_bot в нужную группу. Достаточно права отправлять сообщения; доступ ко всем сообщениям и полные права администратора не нужны.
2. На постоянном Linux-сервере с Docker Compose скопировать `.env.example` в `.env`.
3. В `.env` указать токен из BotFather и подтверждённый числовой ID нужной группы. Ссылка-приглашение не заменяет ID. ID следует получить из события `my_chat_member` или команды, присланной боту из этой группы, и сверить её название. Не угадывать ID по имени группы.
4. Ограничить доступ к `.env`: `chmod 600 .env`.
5. Выполнить `docker compose up -d --build`.
6. Проверить `docker compose logs --tail=40`, затем `/status@msutf_p223_schedule_bot` в группе.

При первом успешном чтении бот пришлёт доступные недельные расписания. Далее проверка каждые 300 секунд. Изменение должно повториться в двух последовательных успешных проверках; обычная задержка уведомления — около 5–10 минут плюс время запросов. Расписание на ещё не опубликованную неделю не выдумывается.

Токен хранить только в `.env` или файле секрета через `TELEGRAM_TOKEN_FILE`; не включать в репозиторий, скриншоты и общедоступные архивы. База хранится в Docker volume `schedule-data`. Для переноса на другой сервер нужно перенести и эту базу, иначе первый запуск снова отправит начальное расписание.

## Проверки

`python -m unittest discover -s tests -v`

`python bot.py --preview` — чтение живого EduPage и предпросмотр сообщений, без Telegram и без токена.

`python bot.py --once` — один цикл с реальной отправкой; нужны токен, ID группы и постоянная база. Нельзя запускать одновременно с основным процессом.

Файл `tests/edupage_130.json` — минимальная выборка реального опубликованного расписания 7–12 сентября; лишние поля и идентификаторы студентов удалены.

## Надёжность и ограничения

- Сравниваются опубликованные недельные таблицы раздела «Расписание». Отдельный раздел замен EduPage не опрашивается.
- Временные ошибки не стирают последнее успешное расписание. /status показывает последнюю успешную проверку.
- Пустая неделя после заполненной блокируется для ручной проверки, поскольку пустой ответ не доказывает отмену всех занятий.
- При неизвестном результате отправки после сетевого обрыва повтор автоматически не производится: это предотвращает дубли, но может потребовать ручной проверки доставки. В базе запись `sent:*` остаётся в состоянии `pending`; /status показывает проблему. Оператор сверяет Telegram, затем либо помечает запись `sent`, либо удаляет конкретную резервную запись для осознанного повтора. Не удалять всю базу.
- Если EduPage поменяет структуру, введёт многонедельные шаблоны в одной публикации или индивидуальные звонки, бот остановит обработку неоднозначных данных. Это требует обновления парсера, а не маскировки ошибки.
- Защита от двух экземпляров использует Linux flock; рекомендуется поставляемый Docker-контейнер.
- Тесты проверяют критические сценарии; абсолютное отсутствие будущих багов и доступность сторонних сервисов не гарантируются.


## Расписание картинкой

Основной репозиторий: https://github.com/speway/uebot .

Каждая неделя публикуется как PNG: спокойная палитра, отдельные пары, время, преподаватели и аудитории. После подтверждения изменения обновляется та же картинка. Через Vercel команды /week и /nextweek возвращают изображение, /today и /tomorrow — текст. На Ubuntu runner нужны Pillow и DejaVu Sans. Токен хранится только в GitHub Actions Secrets.
